# PRE/USD price collection and administration

The existing worker collects the USD price of one PRE from [CoinGecko Demo `/simple/price`](https://docs.coingecko.com/demo/reference/simple-price), using asset ID `presearch`, `vs_currencies=usd`, `include_last_updated_at=true` and `precision=18`. Stored quotations feed a separate publication job. The configured Keyword Market contract's stored rate is authoritative for stake coverage and [click settlement](keyword-market-charges.md).

## Collection and freshness

The BullMQ queue `precommunity-pre-usd-prices` runs a collection at worker startup and every ten minutes. Its shared schedule, global concurrency of one and global limit of one attempt per sixty seconds apply across worker instances and manual refreshes. Each HTTP request has a five-second timeout and one attempt; collection errors leave the previous price intact. The queue is separate from blockchain indexing.

`PreUsdPrice` stores the source, asset, price as `Decimal(38,18)`, provider quotation time (`quotedAt`) and collection time (`fetchedAt`). History is retained. Repeated quotations from the same source and time do not create another record or refresh its collection time. The original JSON number text is preserved when creating the decimal value.

A quotation is displayed as `FRESH` for thirty minutes from CoinGecko's `last_updated_at`, represented by `quotedAt`; fetching the same old quotation does not refresh that age. `FRESH`, `STALE` and `MISSING` remain information for the administrator and form warnings. Publication, stake coverage, new-click billing and `PRICE_PENDING` recovery accept an old positive stored quote indefinitely. A missing first contract quote blocks stake preparation and direct staking, and leaves unpriced click debt pending. Prices that are nonpositive or invalid, and quotation times more than one minute in the future, are rejected. The provider quotation time, rather than `fetchedAt`, becomes the contract timestamp.

## Contract publication and billing

`preUsdPriceE18` stores USD for one PRE with eighteen decimals, and `preUsdPriceQuotedAt` stores the provider timestamp in seconds. The Safe assigns a separate `priceUpdater` through `setPriceUpdater(address)`; zero revokes authorization. Only that updater may call `updatePreUsdPrice(priceE18, quotedAt)`. The contract rejects zero price/timestamp, timestamps over 60 seconds ahead, older quotations and a changed price for the same timestamp. Replaying an identical pair is a no-op. `PriceUpdaterUpdated` and `PreUsdPriceUpdated` supply the indexer with the new state.

The publication queue is `precommunity-pre-usd-publication-<chainId>-<contractAddress>`, with one active operation across instances and a recovery check at startup and every fifteen seconds. It runs independently of automatic click charging and the ten-minute collection queue. An unchanged quotation, missing CoinGecko key or fetch error does not stop reconciliation of an already signed transaction or publication of the latest stored sample. A newer database price does not become the billing price until the publication is accepted and indexed.

`AdPricePublication` retains the quote, chain/contract, signer and nonce, signed transaction/hash, state and receipt block/hash. The worker persists signed bytes before broadcasting. After an uncertain submission or restart it sends the same bytes again and resolves the transaction before preparing another. Confirmation checks use the configured Keyword Market boundary and canonical block hashes; reorgs return the saved transaction to reconciliation. States include `PREPARED`, `SIGNED`, `SUBMITTED`, `RECONCILING`, `CONFIRMED`, `FAILED` and `SUPERSEDED`. Missing permissions, an invalid keystore, insufficient gas, a wrong network/build or an unresolved nonce block publication with an explicit status while preserving the previous stored contract quote.

Stake admission and click billing use integer `floor(bidUsd × 10^30 / preUsdPriceE18)` for six-decimal USD bids and eighteen-decimal PRE balances. API preparation reads position and rate at one block, reports required/available/missing PRE before approval, and rechecks after approval. The contract guards every stake/top-up/bid-only transaction, including manual calls outside the platform. Changing the rate does not rebuild existing rankings or change their opening minimum. New billable clicks freeze the current bid and stored contract rate at their first accepted click, using same-block chain reads or a synchronized projection fallback. Link issuance does not freeze the price. Expired or suppressed deliveries create no new debt, while expiry and later price changes never reprice an already frozen PRE amount. Pending unpriced debt uses the contract quote when one becomes available.

## Admin panel

**Admin → Keyword Marketplace** shows the CoinGecko sample and the contract rate separately, with provider/collection timestamps, freshness warnings, publication status and a BaseScan transaction link. Refresh completion confirms the fetch operation; use publication status and its confirmed transaction to verify that the contract accepted the rate. Dates use the administrator's browser timezone.

Authenticated `SUPER_ADMIN`, `CONTENT_ADMIN` and `FINANCE_ADMIN` users can read `GET /v1/admin/pre-usd-price`. Responses are `no-store`, and price values are decimal strings. Only `SUPER_ADMIN` can submit `POST /v1/admin/pre-usd-price/refresh` and inspect the resulting refresh job through its protected status endpoint. The web client reaches these through the existing `/api` prefix.

Manual refresh adds work to the same queue instead of making an API request from the browser. Concurrent manual requests share a pending manual job without suppressing scheduled collection. The panel disables its refresh button while waiting, polls every two seconds for the first thirty seconds and then every thirty seconds while visible, and rereads the price after completion. An unchanged quotation is reported as having no newer CoinGecko price; waiting for an unavailable worker is not shown as a successful update. Missing configuration, rate limits and queue failures have explicit messages.

## Backend configuration

Set the optional backend variable `COINGECKO_API_KEY` in the environment used by both API and worker. Obtain a Demo API key through [CoinGecko's API dashboard](https://www.coingecko.com/en/api). Never use a `NEXT_PUBLIC_` variable for this key. Whitespace-only values are treated as absent. Without a key, only new price collection and manual refresh are disabled; existing stored samples remain readable and the separate publication/recovery job can continue. Logs do not include the key.

Configure the worker-only `ADS_PRICE_UPDATER_KEYSTORE_PATH` and `ADS_PRICE_UPDATER_KEYSTORE_PASSWORD` for Base, or their `_TESTNET` counterparts for Base Sepolia. Relative paths start at the repository root; preserve password whitespace and quote environment values safely. The encrypted keystore supplies the public updater address; the worker verifies it equals `priceUpdater` and differs from the billing operator. Provision ETH on the selected chain for gas. The updater configuration has no testnet-to-mainnet fallback and must never use `NEXT_PUBLIC_` variables. Do not print keystore contents, passwords or signed transactions in logs. The collection API key is independent of updater authorization and gas funds.

Regenerating `.env.keyword-rehearsal` preserves its existing nonblank key, otherwise copies the nonblank key from the main `.env`. Values are trimmed and checked for safe environment serialization; the generated profile remains private. Preparing this profile does not start services.

`ops/configure-app-runtime.sh` preserves the key from the active production `app.env`, including when preparing a staged environment or changing networks. To provision a replacement, set `PRECOMMUNITY_COINGECKO_API_KEY_STDIN=1` and provide one newline-terminated key on standard input. If `PRECOMMUNITY_SAFE_TRANSACTION_SERVICE_API_KEY_STDIN=1` is also set, input order is **Safe API key first, CoinGecko Demo API key second**, one line each. A blank CoinGecko input retains the existing key; malformed input fails without printing the value or replacing the staged environment. Use a protected secret input mechanism instead of putting key values in command arguments or shell history. Accepted nonblank values contain only letters, digits, `.`, `_`, `~` and `-`.

The existing VPS deployment script reads a nonblank key from the repository `.env` or an explicitly exported override and transfers it over SSH standard input in the same order. No key value is included in SSH arguments or release logs. An absent or whitespace-only local key leaves the active server key in place.

## Operator release

Prepare the updated generated database client and shared packages, then build the updated API, worker and web release before changing runtime processes. Migration `20261009130000_pre_usd_prices` adds the source price history. Migration `20261012143000_keyword_market_price_publication` adds the durable publication journal and nullable checkpoint quote/updater fields; it preserves staking/campaign history and already frozen billing amounts. Generate the matching Prisma client and prepare the compatible release before the operator applies migrations with the old worker stopped. Do not reset, reseed or migrate PRE balances.

The operator applies outstanding migrations to the intended database, provisions the backend key and runs the updated API, worker and web processes. For the isolated rehearsal profile, the existing `db:migrate:sepolia` command targets its configured schema; production uses the existing migration deployment flow and production environment. Other outstanding migrations may have their own release requirements.

Verify the new contract revision on Base Sepolia first, then prepare the Base replacement under a new address. New deployments start without a pause on both networks (`KEYWORD_MARKET_START_PAUSED=0`, `KEYWORD_MARKET_START_PAUSED_TESTNET=0`); the contract already rejects stakes until its first quote is initialized. Run structural bootstrap checks, have the owning Safe authorize the selected updater, wait for the first publication and indexer confirmation, and require active readiness before staking. Preserve old addresses/ABI for manual withdrawals and prepare the old-contract `pause()` Safe JSON for operator review; this release neither submits it nor adds a legacy UI or automatic fund migration.

After release, verify that the admin panel displays both the CoinGecko sample and contract rate, their timestamps and publication proof, that a `SUPER_ADMIN` refresh reaches completion, and that content/finance administrators can read the price without submitting refreshes. The first valid sample is collected when the configured worker starts; publication then requires the dedicated updater to be authorized and funded. Agent implementation and tests do not start, stop or restart local services, apply a live migration, or request the live CoinGecko API.
